# The machine handoff

This directory is **this module's committed copy of the main repo's `.machine.json`** — the
machine's structure as JSON, schema-versioned. It is the whole coupling between the twin and this
control platform.

| File | What |
|---|---|
| `.machine.json` | A **byte-identical** copy of `_docs/context/.machine.json` in the main repository |
| `.handoff.json` | Where that copy came from: the upstream URL and ref, the source commit, its sha256, and when it was synced |

**Never hand-edit either file.** They are written by `_private/tools/sync_machine.py` **in the main
repository**, and hand-editing one makes this module document a machine that does not exist.

## Why a copy, and why here

A vendor module is a separate repository that a user clones into the main repo's root. It has to
build from a **standalone clone** — someone doing TwinCAT work needs no Unity and no twin — so it
cannot read a file across `../` into a repository that may not be there. The copy is committed, so a
fresh clone has one.

It sits in `_workflow/config/` rather than `_docs/context/` because `context/` is **generated by
this module** and swept by its own builder. A committed *input* arriving from another repository
does not belong in a generated *output* directory — it belongs with the other configuration this
module is built against.

**The directory's existence is the opt-in.** `sync_machine.py` writes into a module only if this
directory is there, so a module with no control side yet is skipped rather than scaffolded.

## Refreshing it

From the **main** repository, after rebuilding the twin's knowledge base:

```bash
python _private/tools/build_knowledge.py
python _private/tools/sync_machine.py
```

Then commit the result **here, in this repository** — the main repo cannot commit for you, and a
sync that is never committed is the one way this file goes quietly stale.

A snapshot that is behind the main repo is reported three ways: `sync_machine.py --check` exits
non-zero, `build_knowledge.py` prints a line, and this module's `build_plc_knowledge.py` banners its
`PROVENANCE.md`. A **schema** mismatch is different — that one refuses to build, because the fields
this module reads may have moved.
